# Решения по проекту (ADR-заметки)

Формат короткий: контекст → решение → последствия. Дополняется по ходу этапов,
ссылки на разделы [implementation-plan.md](implementation-plan.md) и [project-brief.md](project-brief.md).

## ADR-001. Основной LLM-провайдер — DeepSeek, запасные — GLM и Qwen

- **Контекст:** Этап 0, пункт «Решить провайдера». Бюджет минимальный, нужен OpenAI-совместимый
  API; позже (Этап 7) появится китайский текст, где Qwen силён.
- **Решение:** основной — **DeepSeek** (`deepseek-chat`), запасной №1 — **GLM** (`glm-4.6`),
  запасной №2 — **Qwen** (`qwen-max`). Локальная опция — Ollama. Реестр: [config/providers.yaml](../config/providers.yaml).
- **Последствия:** смена провайдера = правка YAML, ноль кода (проверяется в Этапе 1).
  Открытые вопросы (оплата из РФ, наличие ключей) могут поменять порядок — это правка конфига,
  не архитектуры.

## ADR-002. Эмбеддинги — bge-m3 локально через Ollama

- **Контекст:** Этап 3 потребует мультиязычный (RU+CN) индекс; данные мануалов наружу отправлять
  не хочется, RAM-бюджет ~2–4 ГБ.
- **Решение:** **bge-m3 локально в Ollama** (dimensions 1024). Если ПК впритык — временный
  fallback на API-эмбеддинги; версия модели хранится у каждого чанка (полный переиндекс при смене).
- **Последствия:** нужен Ollama с потянутой `bge-m3` до Этапа 3; в Этапе 1 эмбеддинги не нужны.

## ADR-003. Чат-UI — Open WebUI (docker), ядро — FastAPI с OpenAI-совместимым API

- **Контекст:** бриф §10 — свой чат-фронтенд не пишем.
- **Решение:** Open WebUI в docker-compose (порт хоста **3000** → контейнер 8080), с Этапа 1 он
  подключается к нашему FastAPI как к OpenAI-провайдеру (`POST /v1/chat/completions`, SSE-стрим).
- **Последствия:** история диалогов, загрузка файлов и мобильный браузер достаются бесплатно;
  вся логика (маршрутизация, антигаллюцинации) живёт в ядре.

## ADR-004. Порты: Open WebUI на хосте 3000

- **Контекст:** на этой машине :8080 занят другим проектом (`cursov-frontend`), :3080 — рабочая
  GUI-среда; :3000 свободен.
- **Решение:** маппинг `3000:8080` в [docker-compose.yml](../docker-compose.yml).
- **Последствия:** телефон в том же Wi-Fi открывает `http://<ip-машины>:3000`.

## ADR-005. Ядро: один OpenAI-совместимый транспорт, алиасы = id моделей (Этап 1)

- **Контекст:** нужен свой бэкенд, в который Open WebUI подключается как к OpenAI-провайдеру;
  провайдер должен переключаться конфигом, без кода.
- **Решение:** один класс `OpenAICompatProvider` (base_url + ключ из `.env` + модель);
  реестр — [config/providers.yaml](../config/providers.yaml); публичные модели — алиасы
  (ключи `models`), уникальность проверяется на старте. Ядро слушает `:8000`;
  WebUI ходит на `http://host.docker.internal:8000/v1` (extra_hosts + host-gateway).
  GLM Coding Plan (z.ai) — запасной провайдер с оговоркой: по ToS план предназначен
  для кодинговых инструментов, не для чата — держим как тестовый/запасной (ADR-001).
- **Последствия:** SSE-стрим релеится как есть (`stream_options: include_usage` для лога
  токенов); лог токенов/стоимости — SQLite `data/usage.db`; стоимость считается, когда
  заполнят `prices` в реестре. QA-набор v0 — [scripts/qa_questions.yaml](../scripts/qa_questions.yaml),
  прогон — [scripts/qa_run.py](../scripts/qa_run.py).

## ADR-006. Конвейер документов: артефакты по doc_id, замок flock, OCR отдельно (Этап 2)

- **Контекст:** «единый парсер мануала» — сердце базы (бриф §3); приёмка через `inbox/`
  с манифестом и статусами (план, Этап 2 и «Конвейер пополнения базы»).
- **Решение:** парсинг — PyMuPDF (текст → чанки ~800 знаков с перекрытием ~200;
  таблицы `find_tables()`, стратегия «lines» с fallback на «text» для таблиц без рамок;
  картинки — рендер 300 dpi, мусор отфильтрован по размеру <80pt). Каждый документ —
  `doc_id = sha256[:16]`, артефакты в `data/processed/<doc_id>/`, оригинал уезжает в
  `data/library/<бренд>/<модель>/<поколение>/<тип>/` из [config/models_catalog.json](../config/models_catalog.json).
  Замок от двойного запуска — flock на `data/pipeline.lock`. Моментные таблицы всегда
  `needs_manual_check: true` (числа 0/8, 1/7 — сверять с оригиналом руками).
- **Последствия:** файлы с неполными метаданными — `needs_review` и остаются в `inbox/`
  (после переименования/уточнения каталога разберутся повторно). Сканов без текстового
  слоя статус `needs_review` с причиной «OCR needed» — OCR добавляется отдельным путём,
  основной конвейер не усложняется. Синтетический PDF в тестах требует шрифта с
  кириллицей (DejaVuSans) — base-14 шрифты кириллицу не кодируют.
